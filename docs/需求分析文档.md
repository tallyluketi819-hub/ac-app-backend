## 1. 项目背景与意义

### 1.1 大学生理财现状

随着高等教育的普及与移动支付的高速发展，大学生群体已成为数字消费的重要参与者。根据相关调查数据显示，超过70%的在校大学生存在月末"透支"现象，近60%的大学生表示从未系统性地对自身消费进行记录与分析。大学阶段是个人财务观念形成的关键时期，良好的记账习惯有助于培养理性消费意识，为未来独立生活奠定基础。然而，由于大学生收入来源单一（主要依赖家庭资助）、消费场景集中（食堂、超市、娱乐）、群体活动频繁（AA出行、聚餐拼单）等特点，通用记账工具往往难以贴合其实际使用场景。

### 1.2 现有记账应用的不足

目前市场上的主流记账应用（如随手记、挖财等）主要面向职场人士或家庭用户设计，存在以下突出问题：

- **功能冗余，上手门槛高：** 现有应用往往包含理财投资、税务管理等大学生不常用的复杂功能，界面信息密度大，新手用户难以快速上手。
- **缺乏群体分账能力：** 大学生群体出行、聚餐、拼单等共同消费场景极为普遍，但多数记账应用缺乏轻量化的AA分账功能，用户往往需要借助微信群手动计算，效率低下且容易出错。
- **缺少校园消费参照：** 通用记账应用无法提供针对校园消费场景的横向对比，用户无法判断自身消费水平是否合理。
- **与微信生态割裂：** 大学生日常高度依赖微信进行社交与支付，独立记账App的切换成本较高，导致记账行为的持续性不足。

### 1.3 本系统的创新点

本项目基于微信小程序平台，专为大学生群体设计，具备以下创新特点：

- **深度融合微信生态：** 依托微信小程序无需独立安装的特点，降低使用门槛，利用微信账号体系简化注册流程。
- **轻量化AA分账模块：** 引入债务净额轧差算法，将多人复杂债务关系自动简化为最少笔数的转账方案，彻底解决群体消费结算难题。
- **校园消费画像分析：** 基于同校用户的匿名消费数据，为个人提供消费健康评分及横向对比，帮助用户了解自身在同校群体中的消费位置，引导理性消费。
- **校园场景精准适配：** 预置食堂、宿舍用品、学习资料、娱乐等大学生高频消费分类，减少用户自定义配置的负担。

## 2. 用户需求分析

### 2.1 目标用户画像

| 维度 | 描述 |
|------|------|
| 年龄范围 | 18 ~ 25岁在校大学生（本科及研究生） |
| 技术背景 | 熟悉智能手机及微信操作，具备基本互联网使用能力 |
| 消费特点 | 月均消费1000~3000元，消费场景集中于校园内部 |
| 社交习惯 | 频繁参与群体活动，AA付款场景多发 |
| 理财意识 | 理财意识薄弱，有记账意愿但缺乏坚持的动力和工具 |
| 设备偏好 | 以Android/iOS智能手机为主，微信日活跃用户 |

### 2.2 用户痛点

1. **记账繁琐，难以坚持：** 传统记账App操作步骤多，大学生在消费后往往忘记及时记录。
2. **分账计算费时费力：** 多人出行或聚餐后，手动计算每人应付金额容易出错，追款过程尴尬。
3. **不知道钱花在哪：** 月末发现余额不足，却无法清晰回溯消费明细，缺乏消费结构分析。
4. **缺少同伴参照：** 不清楚自己的消费水平在同校同学中处于什么位置，无法判断消费是否合理。
5. **应用切换成本高：** 不愿意单独下载安装一个记账App，希望能在微信内直接使用。

### 2.3 用户故事

- **作为一名大学生**，我希望能够快速记录每笔消费（支出类型、金额、备注），以便月末回顾消费明细，了解资金去向。
- **作为寝室长**，我希望记录寝室共同购物的费用后，系统能自动计算出每个人应还给我多少钱，并在还款完成后标记为已结清。
- **作为一名注重生活质量的学生**，我希望看到自己与同校学生的消费对比报告，以及一个直观的消费健康评分，帮助我调整消费结构。
- **作为一名新用户**，我希望能够直接使用微信账号快速注册并登录，不需要填写繁琐的个人信息。

## 4. 非功能性需求

### 4.1 性能需求

- 系统接口在正常负载下响应时间不超过 500ms。
- 账单列表页面首次加载时间不超过 2 秒。
- 数据库查询采用适当索引优化，确保统计接口响应时间合理。

### 4.2 安全性需求

- 用户密码须经过 bcrypt 算法加密存储，禁止明文保存。
- 所有需要鉴权的接口必须验证 JWT Token 的合法性与有效期（有效期设定为 7 天）。
- 用户数据严格隔离，任何用户只能访问和修改自己的账单数据。
- 校园画像模块所用的同校数据须为匿名聚合统计数据，不暴露其他用户的个人信息。

### 4.3 可用性需求

- 系统关键功能（记账、分账）的操作步骤不超过 3 步。
- 所有操作均有明确的成功或失败反馈提示。
- 系统应对网络异常情况进行友好提示，不出现空白页面或无响应状态。

### 4.4 兼容性需求

- 前端小程序兼容微信客户端 8.0 及以上版本。
- 兼容 Android 9.0+ 及 iOS 13.0+ 系统环境。
- 后端 Node.js 运行环境不低于 v16.x。

## 5. 系统边界与约束

### 5.1 系统边界

本系统仅提供消费记录、分账计算与消费画像分析功能，不涉及以下内容：

- 不提供实际的在线转账或支付功能，债务结清仅为状态标记操作。
- 不提供理财建议、投资分析等金融服务。
- 不接入任何第三方银行或支付账户。

### 5.2 假设与约束

- 系统假设所有用户均为在校大学生，以手机号作为唯一账号标识。
- 校园消费画像功能的数据质量依赖于同校用户的记账活跃度，初期数据量不足时，部分对比功能可能受限。
- 分账群组目前不设置最大成员数限制，但建议在 20 人以内以保证算法效率。
- 系统当前版本不支持多货币，所有金额以人民币（元）为单位，精确到小数点后两位。
